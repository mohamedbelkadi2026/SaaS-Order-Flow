FIX — "Frais livr. (fichier)" reste à 0,00 DH dans le rapport final du mode
"Import CSV" même quand le fichier importé a bien une colonne de frais de
livraison, parce que celle-ci s'appelle très probablement "FRAIS DE
LIVRAISON" (le nom exact utilisé partout ailleurs dans la plateforme, y
compris dans l'export commandes) — et aucun des mots-clés de détection
automatique ne matche ce nom précis.

CAUSE (confirmée dans le code)
client/src/pages/profit-analyzer.tsx, ~ligne 536 :
```ts
shipping: detectCol(headers, ["shipping cost", "frais livr", "frais exp", "cout livr", "shipping", "frais port", "frais transport", "delivery cost"]),
```
`detectCol` (ligne 42-54) essaie d'abord une correspondance EXACTE, puis un
`includes()` en repli. Aucun mot-clé de la liste n'est un sous-texte
contigu de "frais de livraison" — le mot "DE" entre "FRAIS" et "LIVRAISON"
casse la correspondance substring ("frais livr" n'apparaît PAS tel quel
dans "frais de livraison"). Résultat : la colonne n'est jamais détectée
automatiquement, `shipping` reste vide dans `colMap`, donc chaque ligne est
parsée avec `shipping: 0`.

FIX — Ajouter "frais de livraison" (et quelques variantes courantes) à la
liste de mots-clés :

```ts
shipping: detectCol(headers, [
  "frais de livraison",   // ← AJOUTÉ, nom exact utilisé dans la plateforme
  "frais de livr",        // ← AJOUTÉ, variante tronquée
  "shipping cost",
  "frais livr",
  "frais exp",
  "cout livr",
  "shipping",
  "frais port",
  "frais transport",
  "delivery cost",
]),
```
