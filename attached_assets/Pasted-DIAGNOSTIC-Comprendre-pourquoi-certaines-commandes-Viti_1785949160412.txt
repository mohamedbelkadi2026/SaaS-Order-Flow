DIAGNOSTIC — Comprendre pourquoi certaines commandes Vitips Express
échouent avec "produit invalide" ou une erreur de ville, alors que le
produit et la ville semblent corrects dans l'interface.

PISTES DÉJÀ IDENTIFIÉES DANS LE CODE (à confirmer par les logs)

1) `getProductName()` (server/routes.ts, ~ligne 1635) ne prend QUE le
   PREMIER article de la commande :
   ```ts
   const getProductName = (order: any) =>
     order.rawProductName ||
     (order.items?.length > 0
       ? (order.items[0].rawProductName || order.items[0].product?.name || 'Produit')
       : 'Produit');
   ```
   Si le 1er article n'a ni `rawProductName` ni `product` lié (produit non
   rattaché au catalogue — même bug déjà rencontré avec d'autres
   transporteurs), le nom envoyé à Vitips devient le mot générique
   `"Produit"` — que Vitips rejette très probablement comme "invalide" (il
   ne correspond à aucun produit connu de leur système). C'est la piste la
   plus probable pour les erreurs "produit invalide".

2) Pour la ville, même si le champ affiche "AGADIR" dans l'interface,
   l'ERREUR précise renvoyée par Vitips ("La ville du client destinataire
   ...") n'est pas visible en entier dans le screenshot — il faut le
   message complet pour savoir si c'est un problème d'orthographe, de ville
   non synchronisée pour CE compte précis, ou autre chose.

FIX ADDITIONNEL (probable, à appliquer en même temps) — utiliser TOUS les
articles de la commande, pas seulement le premier

Remplacer `getProductName` par :
```ts
const getProductName = (order: any) => {
  if (order.rawProductName) return order.rawProductName;
  if (!order.items || order.items.length === 0) return null; // ← plus de fallback "Produit" générique
  const names = order.items
    .map((it: any) => it.rawProductName || it.product?.name)
    .filter(Boolean);
  return names.length > 0 ? names.join(" + ") : null;
};
```

Et, juste avant d'appeler `buildPayload`/l'envoi vers Vitips, si
`getProductName(order)` renvoie `null` (aucun nom exploitable trouvé), NE
PAS envoyer la commande et retourner une erreur claire côté plateforme
(`"Commande #X — aucun produit identifiable, impossible d'expédier via
Vitips"`) plutôt que de laisser Vitips la rejeter avec un message opaque.
