CRITICAL FIX: Vitipsexpress statuses are being saved as RAW French text instead of mapped platform statuses.

Orders show: "Reçu par livreur", "Expédié", "Programmé", "En attente ramassage"
They should show: "transit", "transit", "unreachable", "Attente De Ramassage"

PROBLEM: In server/routes.ts, POST /api/shipping/vitips/sync,
the background sync is calling storage.updateOrderStatus() with result.status (which is the mapped status).
But something is wrong — check if the mapping is returning null and the raw status is being saved instead.

In the sync loop, add this guard:
  if (!result.status) {
    console.warn(`[VITIPS-SYNC] ⚠️ No mapping for raw="${result.rawStatus}" — skipping`);
    continue;
  }

Also make sure we NEVER save rawStatus to the order.status field.
Only save result.status (the mapped value like "transit", "delivered", etc.)

ALSO: For existing orders that already have wrong raw statuses in DB,
add a one-time fix endpoint POST /api/vitips/fix-raw-statuses that:
1. Finds all orders where status IN ('Reçu par livreur', 'Expédié', 'Programmé', 'En attente ramassage', 'En attente de ramassage', 'Recu par livreur')
2. Maps them to correct platform status using VITIPS_STATUS_MAP
3. Updates each order

The mapping for these raw statuses:
'Reçu par livreur' → 'transit'
'Recu par livreur' → 'transit'
'Expédié' → 'transit'
'Expedie' → 'transit'
'Programmé' → 'unreachable'
'Programme' → 'unreachable'
'En attente ramassage' → 'Attente De Ramassage'
'En attente de ramassage' → 'Attente De Ramassage'
'Livré' → 'delivered'
'Livre' → 'delivered'
'Refusé' → 'refused'
'Refuse' → 'refused'

Call this endpoint once after deploy to fix all historical wrong statuses.
