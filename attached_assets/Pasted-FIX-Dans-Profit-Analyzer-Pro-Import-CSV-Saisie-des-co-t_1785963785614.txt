CAUSE 1 (bug critique confirmé) — "X2" dans le nom du produit est
interprété à tort comme une quantité "×2"

client/src/pages/profit-analyzer.tsx, fonction `matchStockCost` (~ligne
950-955) :
```ts
const xMatch = cleanPart.match(/^(.+?)\s+[Xx](\d+)\s*(.*)$/);
if (xMatch) {
  qty = Math.max(1, parseInt(xMatch[2], 10));
  nameForMatch = (xMatch[1] + (xMatch[3] ? " " + xMatch[3] : "")).trim();
}
```
Cette regex, censée détecter une quantité groupée du type "T-shirt X2"
(2 unités), matche AUSSI "Sandale En Cuir Rf210 X2 Noir - 43" — "X2" ici
fait partie du NOM DU MODÈLE, pas d'une quantité. Le nom de recherche
devient alors "Sandale En Cuir Rf210 Noir - 43" (le "X2" a disparu), qui ne
correspondra JAMAIS au vrai produit catalogue "Sandale En Cuir Rf210 X2
Noir" — d'où "non trouvé dans le stock" systématique pour TOUS les
produits "Rf210 X2 ...".

FIX — Essayer d'abord un match SANS toucher au nom ; n'appliquer
l'extraction de quantité "X2" que si cette tentative directe échoue
complètement (comportement en repli, jamais prioritaire) :

```ts
// Extract embedded quantity "X2" / "x 2" — MAIS seulement en dernier
// recours : essayer d'abord de matcher le nom TEL QUEL (le "X2" peut faire
// partie du nom du modèle, ex: "Rf210 X2", pas d'une quantité groupée).
let qty = 1;
let nameForMatch = cleanPart;

const directMatch = matchSingleItemCost(cleanPart, active);
if (directMatch === null) {
  const xMatch = cleanPart.match(/^(.+?)\s+[Xx](\d+)\s*(.*)$/);
  if (xMatch) {
    const candidateName = (xMatch[1] + (xMatch[3] ? " " + xMatch[3] : "")).trim();
    // Ne retenir l'interprétation "quantité" QUE si ça matche effectivement
    // quelque chose — sinon on garde le nom d'origine (le X2 ne voulait pas
    // dire "quantité" ici, sinon ça matcherait déjà).
    if (matchSingleItemCost(candidateName, active) !== null) {
      qty = Math.max(1, parseInt(xMatch[2], 10));
      nameForMatch = candidateName;
    }
  }
}

let unitCost: number | null = matchSingleItemCost(nameForMatch, active);
```
